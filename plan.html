개발 방향과 남은 5일 계획

다국어 정착 로드맵 안내 에이전트를 8일 대회 안에 Level 3(MVP)으로 완성하기 위한 정리입니다. 대회 공고문의 심사 원칙과 팀 개발계획서를 맞춰 보고 정했습니다.

개발기간 9/29 – 10/6 오늘 10/2 · 4일차 서류심사 10/7 – 8 발표심사 10/12
핵심 판단

규칙 기반 웹앱이 아니라 에이전트로 보여야 합니다

공고문 심사 원칙

  • 기능 수보다 AI Agent다운 문제 해결 과정과 실제 동작 여부를 우선 평가
  • 시연영상은 입력 → 판단 → 도구 실행 → 결과가 보이게 구성
  • 기술설명서 항목: Goal, Workflow, AI, Tool/API/Data, Memory/Feedback, 신규개발분

계획서의 기능(로드맵, 위험도 점수, D-day, 신청서 생성)은 대부분 규칙 기반입니다. 검증이 쉽다는 장점은 살리되, 그대로 두면 설문 폼과 조건문으로 이루어진 웹앱으로 보일 위험이 있습니다.

코드가 맡는 일

정확해야 하는 부분

날짜 계산, 위험도 채점, 지원사업 매칭, 신청서 값 채우기. 기존 규칙 로직을 그대로 도구(Tool)로 만듭니다. 계획서의 "직접 검증 가능" 원칙이 유지됩니다.

Claude가 맡는 일

판단·대화·설명

사용자 언어로 대화하고, 빠진 정보를 되묻고, 어떤 도구를 언제 쓸지 결정하고, 결과를 쉬운 말로 풀어 줍니다. 여기서 에이전트다움 점수를 얻습니다.

과제명이 "능동 케어"이므로 재방문 시 에이전트가 먼저 말을 거는 기능을 꼭 넣습니다. 비용은 작고, Memory/Feedback 항목과 능동성을 동시에 보여 줍니다.

시연 화면 옆에 도구 호출 로그 패널을 두면(예: search_programs(region=김해, category=한국어교육) → 4건) 영상에서 판단과 도구 실행 과정이 자연스럽게 드러납니다.

시연

핵심 End-to-End 시나리오 (시연영상 3분)

  1. 베트남 출신 근로자 페르소나가 베트남어로 "김해에 왔고 아이가 있어요"라고 입력
  2. 에이전트가 빠진 정보(입국 시점, 체류 종료일 등)를 되물어 프로필 완성 → save_profile
  3. build_roadmap과 search_programs → 순서가 있는 로드맵과 실제 김해 지원사업 카드
  4. score_risk 점수가 기준 이하이면 멘토·상담 연계를 먼저 제안
  5. "한국어 교실 신청하고 싶어요" → generate_application_doc → docx 다운로드
  6. 재방문 시 에이전트가 먼저 D-day와 남은 단계를 안내

체크리스트

제출·심사에서 놓치기 쉬운 것

  • 출처·AI 활용 신고서(별지2): Claude, LangChain, AI 코딩 도구, 지원사업 데이터 출처를 모두 기재. 사용 자체는 감점 사유가 아님
  • 정량 목표 증빙: 로드맵 생성 10초 이내(응답시간 로그), DB 20건 이상, 신청서 반영 정확도 100%(테스트 케이스 표)
  • 안전장치: 시스템 프롬프트에 비자·법률 판단 금지, 공식 기관 연결 원칙 명시
  • 시연 데이터: 실제 개인정보 대신 가상 페르소나 사용
  • API 키: 저장소에는 .env.example만 올림
  • 필수 제출물 5종: 개발완료보고서(5p), AI Agent 기술설명서(1p), 소스코드/저장소, 시연동영상(3분), 발표자료(10장)
