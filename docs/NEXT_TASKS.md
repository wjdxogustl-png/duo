## 작업 규칙

- 파일을 통째로 새로 쓰지 말고, 필요한 부분만 고친다. 기존 기능(맥락 추론 프롬프트, 액션 카드 검증, 변경 파이프라인, 신청서 초안)을 지우지 않는다.
- 작업 하나마다 `backend` 폴더에서 `python -m pytest -q`를 실행해 기존 테스트가 모두 통과하는지 확인하고, 새 기능에는 테스트를 추가한다.
- 프론트엔드를 고쳤으면 `npm run build`가 성공하는지 확인한다.
- 화면에 새로 나오는 문구는 `frontend/src/i18n.js`에 5개 언어(ko, en, vi, ja, zh)로 모두 넣는다.
- 전화번호를 새로 넣을 때는 공식 출처 URL과 확인일을 함께 남긴다. 출처를 확인할 수 없는 번호는 넣지 말고 팀에게 묻는다.
- 작업 하나를 커밋 하나로 남긴다. `.env`는 커밋하지 않는다.
- 개발·시연 LLM은 Claude(`claude_agent`)다. 동작 확인도 이 모드로 한다.

### B1. 도구 실행 과정 실시간 표시

**목적**: 로드맵을 만드는 턴은 약 20초가 걸리는데, 지금은 그동안 "생각하는 중"만 보인다. 에이전트가 도구를 부를 때마다 작업 기록 패널에 바로 한 줄씩 나타나게 해서, 기다리는 시간을 "에이전트가 일하는 모습"으로 바꾼다.

**설계 (기존 `/api/chat`은 그대로 두는 방식)**
1. 백엔드에 진행 상황 저장소를 둔다: 사용자 ID별로 "지금 처리 중인 턴의 도구 호출 목록"을 메모리에 보관(`backend/app/progress.py` 같은 작은 모듈).
2. 도구가 실행될 때마다 이 저장소에 추가한다.
   - LangChain 루프(`agent.py`의 `_run_loop`): 도구 실행 직후 추가.
   - `claude_agent`: MCP 서버는 별도 프로세스라 메모리를 공유하지 못한다. `claude_agent_llm.py`에서 `subprocess.run` 대신 `subprocess.Popen`으로 바꾸고 stdout의 stream-json을 한 줄씩 읽으면서 `tool_use`가 나올 때 추가한다. 최종 결과 처리(연결 상태 확인, 기록 파일 우선, 오류 메시지)는 지금과 똑같이 유지한다.
3. `GET /api/progress/{user_id}`를 추가해 지금까지의 도구 목록(도구 이름, 시작 시각, 끝났는지)을 돌려준다. 턴이 끝나면 목록을 비운다.
4. 프론트엔드: `busy`인 동안 0.7초마다 `/api/progress/{user_id}`를 불러, 작업 기록 패널 맨 위에 "진행 중" 묶음으로 보여 준다. 새 항목은 살짝 나타나는 효과를 준다. 응답이 오면 지금처럼 최종 기록으로 바꾼다.
5. "생각하는 중" 말풍선 대신 가장 최근 도구를 사람이 읽기 좋은 말로 보여 준다(예: `search_programs` → "지원사업을 찾는 중"). 5개 언어.

**완료 기준**
- 테스트: 진행 저장소에 추가·조회·초기화가 되고, 다른 사용자 ID끼리 섞이지 않는다.
- 테스트: 가짜 CLI가 stream-json을 여러 줄 내보낼 때 tool_use가 순서대로 진행 저장소에 쌓인다(기존 가짜 CLI 테스트 방식 활용).
- `claude_agent`로 로드맵 턴을 보낼 때 작업 기록에 도구가 하나씩 나타나는 것을 화면에서 확인.
- 기존 테스트 모두 통과, `npm run build` 성공.
